# 004: Terminal User Interface (TUI) & Config

- **Status:** Implemented
- **Created:** 2026-11-20
- **Updated:** 2026-11-20

## Problem

Users need an interactive way to scan for their BLE HR monitor and Shelly Dimmer, monitor live HR and fan speed, and override fan speed or curve values during a ride.

## User Story

As an indoor cyclist, I want a clean TUI to discover/select my devices and monitor/control my fan speed in real time, with my preferences saved locally.

## Acceptance Criteria

- [x] Persist selected device IDs and HR thresholds (`MinHR=120`, `MaxHR=165`, `MinSpeed=15`, `MaxSpeed=100`) to `~/.config/opendraft/config.json`.
- [x] Provide a Bubble Tea **Discovery View** showing live BLE HR and mDNS Shelly scan results with keyboard navigation and selection.
- [x] Provide a Bubble Tea **Dashboard View** with keyboard-navigable **START / STOP** and **SCAN DEVICES** buttons (`Tab`/`←`/`→` + `Space`/`Enter`/click), live BPM, target & applied fan speed (%), `AUTO`/`MANUAL` mode, editable curve values (`c`), and keyboard shortcuts (`a` toggle mode, `+`/`-` manual speed, `0` off, `q` quit).
- [x] Support a `--mock` CLI flag so the TUI and control loop can be tested without physical BLE/Shelly hardware.
- [x] Unit tests for config persistence and Bubble Tea `Update` state transitions.

## Design & Architecture

- `internal/config`: JSON config load/save.
- `internal/tui`: Bubble Tea `Model` (`discovery.go`, `dashboard.go`, `styles.go`, `model.go`).
- `cmd/opendraft/main.go`: CLI flags (`--config`, `--mock`) and wiring.

## Out of Scope

- Web UI or desktop GUI.
- Historical workout charts or FIT file export.
